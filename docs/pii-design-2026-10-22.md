# 전송 전 비식별화 설계 메모 (2026-10-22)

프롬프트와 첨부 문서가 외부 AI 서비스로 그대로 나가던 구조에, 보내기 직전 로컬 검토 관문을 둔다.

## 원칙

- **탐지는 전부 이 기기 안에서.** 탐지를 위해 외부 AI에 보내면 의미가 없고 지시문(API 금지)에도 맞지 않는다. 정규식·사전 규칙만 쓴다.
- **최종 결정은 사용자.** 규칙은 놓치는 항목이 있다는 전제다. 검토 모드(기본)는 후보가 있거나 첨부를 읽지 못하면 패널을 연다.
- **원문은 이 기기 메모리에만.** 대응표(원문↔기호)는 클라우드에 올리지 않는다. 비교 기록에는 가린 텍스트와 개수·종류·첨부 처리만 남긴다(`responses._pii`, 파이프라인은 `_meta.pii`).

## 흐름

```
보내기 → 접두어 결합 → preparePayload(프롬프트, 첨부)
  ├ 첨부: 형식 판별 → 텍스트 추출(txt·csv 그대로 / docx·pptx·xlsx·PDF 변환 / 이미지·스캔 불가)
  ├ 출처: 프롬프트 · 첨부 본문 · 첨부 파일명
  └ 탐지 → 원문별 묶음(같은 원문 = 같은 기호, 출처별 등장 횟수)
모드 끔   → 원문 그대로
모드 검토 → 후보 없음·첨부 읽힘이면 그대로 / 아니면 검토 패널
모드 자동 → 모두 가림 (첨부를 못 읽으면 패널)
검토 패널 → 체크·직접 추가·항상 허용 → finalizePayload → 가린 텍스트 + 다시 만든 첨부
→ 기존 동시 전송·파이프라인 경로 (검증·수정 단계도 같은 기호를 이어 씀)
```

## 탐지 대상

| 종류 | 규칙 | 신뢰도 |
|---|---|---|
| 주민·외국인등록번호 | 생년월일 형식 + 성별 1~8 + 6자리 | 높음 |
| 전화 | 휴대폰·지역번호·+82 | 높음 |
| 이메일 | 표준 형식 | 높음 |
| 카드 | 16·15자리 + Luhn | 높음 |
| 계좌 | "계좌·통장·입금·송금·은행" 뒤 25자 안 숫자열 | 높음 |
| 여권 | "여권" 근처 M12345678 / M123A4567 | 높음 |
| 운전면허 | 지역-2-6-2 | 높음 |
| 사업자등록번호 | 3-2-5 + 검증 숫자 | 높음 |
| IP | IPv4 | 높음 |
| 주소 | 시·군·구가 하나 이상 + 도로명·지번 + 동·호 | 추정 |
| 이름 | 성씨 + 1~2자 + 호칭·직함, 또는 직함 + 성씨 + 2자 | 추정 |
| 기관 | 법인 표기(주식회사·(주)·재단법인…), 고유명 + 기관 접미어(대학교·병원·은행…), 영문 법인 | 추정 |
| 사용자 사전 | 설정의 "항상 가릴 단어", 검토 패널의 직접 추가 | 높음 |

오탐 방지: 성씨로 시작하는 일반 단어 목록(한국·이번·연락처·보고서…), 일반 명사 + 기관 접미어(종합병원·시중은행…), 날짜·금액·버전은 형식상 걸리지 않게 했다. "가리지 않을 단어"와 검토 패널의 "항상 허용"으로 사용자가 보완한다.

## 가림 규칙

- 기호: 이름·기관은 `[인물A]`, `[기관A]`(A~Z, AA…), 나머지는 `[전화1]`처럼 숫자.
- 탐지 위치만이 아니라 **텍스트 전체의 같은 원문**을 바꾼다. 호칭 없이 다시 나온 이름, 첨부 안의 같은 번호도 가려진다.
- 이름은 경계를 지킨다: 앞이 한글·영숫자가 아니고 뒤가 조사·호칭이거나 한글이 아님. "김민"이 "김민지"를 건드리지 않는다.
- 번호는 구분자(-, 공백, .) 차이를 같은 번호로 본다.
- 법인 표기로 잡은 기관은 표기 없이 쓴 이름도 같은 기호로 바꾼다("(주)한빛소프트" → "한빛소프트"도).
- 긴 원문부터 바꿔 부분 겹침을 막는다.

## 첨부 문서

| 형식 | 처리 | 보내는 파일 |
|---|---|---|
| txt·md·csv·tsv·json·코드 등 | 본문 그대로 가림 (UTF-8, 실패 시 EUC-KR) | `이름_가림.원래확장자` |
| docx | 본문·표(Markdown 표)·제목·목록·머리글·바닥글·각주·미주·메모 | `이름_가림.txt` |
| pptx | 슬라이드 순서대로 텍스트 + 발표자 노트 | `이름_가림.txt` |
| xlsx | 시트별 Markdown 표(공유 문자열·인라인·숫자), 시트당 2,000행 | `이름_가림.txt` |
| PDF | 페이지별 텍스트(pdfjs, 300쪽), 글자가 거의 없으면 스캔본으로 판정 | `이름_가림.txt` |
| 이미지·스캔 PDF·hwp 등 | 검사 불가 | 원본 그대로 또는 첨부 빼기만 |

파일명도 가린다(`고객미팅_홍길동.docx` → `고객미팅_[인물A]_가림.txt`). 변환 파일 첫 줄에 원본 형식과 "서식·이미지 제외" 안내를 넣는다.

## 복원

요약 카드의 "원래 이름으로 보기"와 동시 전송 내보내기의 "원문 복원"이 이 기기에서만 기호를 원래 값으로 되돌린다. 서비스 패널 화면은 가린 상태 그대로다. 모델이 `[인물 A]`처럼 띄어 쓰거나, 응답의 Markdown 변환이 `\[인물A\]`로 이스케이프해도 복원된다.

## 알려진 한계

- 호칭 없는 이름, 외국인 이름(예: John Kim), 약어로 쓴 기관명은 놓칠 수 있다. → 직접 추가, 항상 가릴 단어
- 첨부 문서의 이미지 속 글자, 스캔 PDF, hwp는 읽지 못한다.
- docx의 텍스트 상자·SmartArt, xlsx의 수식 결과가 아닌 수식 자체, pptx의 차트 데이터는 빠질 수 있다.
- 서비스에 로그인한 계정 자체의 신원, 대화 맥락으로 추론 가능한 정보는 범위 밖이다.

## 실기 확인 (2026-10-22)

개인정보가 든 Word 회의록(이름 2·기관 1·주소·전화·이메일)과 가린 프롬프트를 동시 전송. Claude·Gemini·Perplexity가 `.txt` 변환 첨부를 받아 기호를 유지한 채 요약·메일 초안을 작성했다. ChatGPT는 대화 화면이 개편되어 첫 시도에서 입력창을 찾지 못했고, 입력창·전송 버튼·답변 셀렉터를 실측 갱신한 뒤 재전송해 같은 결과(기호 유지)를 확인했다. 네 서비스 모두 `.txt` 변환 첨부를 받았다.
