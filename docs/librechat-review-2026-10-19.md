# LibreChat 구조 분석과 질서 반영사항 (2026-10-19)

대상: https://github.com/LibreChat-AI/LibreChat (MIT, ★46k, fork 9.5k, TypeScript, 2026-10-19 기준 활발히 갱신)

## 1. LibreChat은 무엇인가

"향상된 ChatGPT 클론". 셀프 호스팅 웹앱으로, 여러 AI **제공자의 API**(OpenAI·Anthropic·Google·Bedrock·Azure·Ollama·OpenAI 호환 커스텀 엔드포인트)를 한 채팅 화면에 모은다. 다중 사용자(OAuth2·LDAP·이메일), 관리자 패널, 에이전트(도구·MCP·파일 검색·코드 실행), 에이전트 마켓, 대화 포크, 전문 검색(Meilisearch), 메모리, 아티팩트, 임시 채팅, 대화 가져오기, 토큰 사용량 추적과 잔액(크레딧).

사용자가 전달한 소개문("따로 결제 중이면 이것부터", "대화 중간에 모델을 바꿔도 이어감", "쓴 만큼만 냄", "회사에 하나 깔아 직원이 각자 계정으로")은 정확히 이 구조에서 나온다.
- 모델을 중간에 바꿔도 이어지는 것은 대화 이력을 서버가 보관하고 매 요청에 API로 다시 보내기 때문이다.
- 쓴 만큼 내는 것은 구독이 아니라 API 종량 과금이기 때문이다. 가끔 쓰는 사람에게는 싸고, 많이 쓰는 사람에게는 구독보다 비쌀 수 있다.
- 회사 배포는 다중 사용자·역할·잔액 관리가 서버에 있기 때문이다.

## 2. 구조

| 영역 | LibreChat | 질서 |
|---|---|---|
| 형태 | 서버(Node/Express + MongoDB + Redis + Meilisearch) + 브라우저 UI(React/Vite). Docker Compose·Helm 배포 | 데스크톱 앱(Tauri 2, Rust + React). 서버 없음 |
| 모델 접근 | 제공자 API 키(서버가 보관), OpenAI 호환 엔드포인트 | 각 서비스 **웹 화면**에 DOM 주입. API·키 없음(지시문) |
| 과금 | API 종량. 토큰 사용량 추적·잔액·거래 기록 | 사용자의 기존 구독. 과금 추적 없음 |
| 사용자 | 다중 사용자, 역할·그룹, 관리자 | 1인. 기기 간 동기화만(Supabase) |
| 설정 | `librechat.yaml`(엔드포인트·모델 스펙·인터페이스 토글) | `services/*.json`(셀렉터), 앱 설정 |
| 모노레포 | `api/`, `client/`, `packages/{data-provider,data-schemas,api,client,chat}`, `e2e/`(Playwright), `helm/`, `otel/` | 단일 패키지 + `src-tauri/`. vitest 유닛, 파일 하네스 |
| 다국어 | `client/src/locales` 다수 | 한국어 고정 |
| 품질 | husky, e2e, 테스트, 타입 패키지 분리(zod 스키마) | tsc + vitest. CI 없음 |

핵심 차이는 하나다. LibreChat은 **API 위에 세운 다중 사용자 서버**이고, 질서는 **구독 웹 UI 위에 세운 개인 데스크톱 앱**이다. 질서가 LibreChat처럼 되려면 API를 써야 하는데, 그것은 지시문이 금지하고 2026-09-29에 사업화와 함께 접은 방향이다. 따라서 "구조를 가져온다"가 아니라 "구조 위에서 검증된 **사용자 경험과 개발 관행**을 가져온다"가 맞다.

## 3. 질서에 반영할 것

### 지금(공개 저장소 직후, 작고 효과 큼)

1. **PR용 CI**: GitHub Actions에서 `tsc --noEmit`과 `vitest`를 PR마다 실행. LibreChat의 e2e·husky 수준은 과하지만, 외부 PR을 받기 시작한 지금 최소선이다. Windows 빌드 워크플로우는 이미 있으니 그 옆에 둔다.
2. **services JSON 스키마 검증**: LibreChat이 `data-schemas`(zod)로 설정을 검증하듯, `services/*.json`의 필드(선택자 문자열·`kind`·`afterFileBroadcast`·`generating`)를 zod로 검증하고 오류를 앱 헤더의 "서비스 정의 오류"에 구체적으로 표시. 기여자가 셀렉터 PR을 낼 때 실수를 잡는다. `npm run check:services` 스크립트도 함께.
3. **임시 전송(기록 저장 안 함)**: LibreChat의 Temporary Chat. 민감한 프롬프트를 보낼 때 비교 기록·판정을 Supabase에 남기지 않는 토글. 전송 바에 스위치 하나.
4. **기록 내보내기**: 비교 기록 1건을 Markdown(질문·답변·검증 판정·수정본)으로 복사/저장. LibreChat의 대화 export와 같은 역할이고, 설계 문서가 말한 "기록 자산화·Obsidian 연결"의 첫 단계.

### 다음

5. **프롬프트 변수**: LibreChat 프롬프트 라이브러리의 `{{변수}}`. 질서 라이브러리 프롬프트에 자리표시자를 두고 삽입 시 값을 묻는다. 검증 렌즈가 이미 `{question}`·`{answer}`를 쓰므로 같은 치환기를 재사용.
6. **기록 검색과 태그**: LibreChat은 Meilisearch, 질서는 Supabase의 `ilike`/전문 검색으로 충분. 비교 기록·메모에 태그를 붙이고 검색하는 화면. 성적표 옆에 "기록" 탭.
7. **전송 횟수 카운터**: LibreChat의 토큰 사용량 추적을 질서식으로 번역하면 "서비스별 오늘 전송 횟수"다. 무료 플랜 한도(ChatGPT Free의 빈 응답 현상)를 미리 경고할 수 있다. 전송 시각만 로컬에 기록하면 된다.
8. **워크스테이션별 프롬프트 접두어**: LibreChat의 메모리·프리셋의 시스템 프롬프트를 DOM 방식으로 옮긴 것. 워크스테이션에 "항상 앞에 붙일 문장"을 저장해 전송 시 결합. API 없이 할 수 있는 유일한 "개인화".

### 보류·하지 않음

- **API/BYOK 모드, 다중 사용자, 잔액**: 지시문 위배이고 서비스 방향이 아니다. LibreChat이 그 자리를 이미 잘 채우고 있다(질서를 쓰는 사람이 종량 과금을 원하면 LibreChat을 쓰면 된다).
- **서비스 안에서 모델 전환 자동화**(ChatGPT의 모델 선택 메뉴를 DOM으로 조작): 가능하지만 셀렉터가 가장 자주 바뀌는 부분이라 유지비가 크다. 이슈로 요청이 쌓이면 검토.
- **다국어 UI**: 공개 저장소라 영어 사용자가 올 수 있으나, 한국어 검증 렌즈·템플릿이 핵심 가치다. README 영어 요약으로 충분하고, 요청이 오면 `ko/en` 리소스 분리를 검토.
- **에이전트·MCP·RAG·아티팩트**: 모두 API 전제.

## 4. 포지셔닝 한 줄

LibreChat은 "API를 하나의 채팅으로", 질서는 "구독 중인 서비스들을 하나의 검증 작업대로". 겹치지 않는다. 소개문에서 비교를 받으면 "이미 구독을 내고 있고, 여러 모델이 서로 검증하게 하고 싶으면 질서"라고 답하면 된다.
