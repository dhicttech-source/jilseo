# 질서 사용 설명서

질서(疾書)는 질문 하나를 여러 AI 웹 서비스(ChatGPT · Claude · Gemini · Grok · Perplexity)에 한 번에 보내고, 답을 나란히 비교하거나 서로 검증하게 하는 데스크톱 앱입니다. API 키 없이 각 서비스의 웹 화면에 직접 입력하므로, 쓰고 있는 무료·유료 계정을 그대로 씁니다.

처음이라면 **1 → 2 → 3 → 4** 순서로 한 번씩 해 보세요. 10분이면 됩니다.

---

## 화면 구성

```
┌ 헤더 ─ 질서 · 워크스테이션 · 진단 · 셀렉터 JSON 폴더 · 성적표 · 설정 · 도움말 ┐
│                                                                              │
│   스테이지: 서비스 패널들이 나란히 (패널마다 이름·상태·역할·메모·최대화)      │
│                                                                              │
├ 독: 패널에 올릴 서비스 고르기 · 열 수 · 웹슬롯(일반 URL) 추가 ──────────────┤
├ (결과가 있으면) 판정 요약 카드 또는 응답 평가 줄 ───────────────────────────┤
└ 전송 바: 🔓 · 비식별화 · 📎 · 동시/생성→검증 · 접두어 · 📚 · 입력창 · ▶ 보내기 ┘
```

- **패널**은 각 서비스의 실제 웹 화면입니다. 그 안에서 평소처럼 스크롤하고 클릭할 수 있습니다.
- **전송 바**에 쓴 질문이 스테이지의 패널들로 들어갑니다. `⌘ Enter`(Windows는 `Ctrl Enter`)로도 보냅니다.

## 1. 처음 실행과 로그인

1. 설치
   - macOS: Releases의 dmg를 열어 응용 프로그램 폴더로 옮깁니다. "확인되지 않은 개발자"라고 막히면 dmg 안의 `처음 실행하는 법.txt`대로 하세요(터미널에 `xattr -cr /Applications/jilseo.app`, 또는 시스템 설정 → 개인정보 보호 및 보안 → "그래도 열기").
   - Windows: Releases의 `x64-setup.exe`를 실행합니다. 첫 실행 안내는 [windows-first-run.md](windows-first-run.md).
2. 첫 화면 안내를 읽고 **시작하기**.
3. **각 패널 안에서 직접 로그인**합니다. 앱은 비밀번호·쿠키를 다루지 않고 서비스 웹 화면에 맡깁니다. 한 번 로그인하면 재시작해도 유지됩니다.
   - 패스키(지문·Face ID)는 앱 안에서 쓸 수 없습니다. "다른 방법 → 비밀번호"를 고르세요.
   - Google 로그인 팝업이 끝나고도 안 닫히면 직접 닫으세요.
4. 쓰지 않을 서비스는 아래 **독**에서 이름을 눌러 스테이지에서 내립니다. 패널 수와 열 수도 독에서 바꿉니다.

> 무료 플랜도 됩니다. 다만 무료 플랜은 긴 질문이나 검색이 붙는 질문에서 답이 비거나 끊길 수 있습니다(아래 "막힐 때").

## 2. 동시 전송: 같은 질문, 여러 답 비교

1. 전송 바의 모드 버튼이 **동시**인지 확인합니다(초록색 "생성→검증"이면 한 번 눌러 바꿉니다).
2. 입력창에 질문을 쓰고 **▶ 보내기**.
3. 패널 머리에 `입력 중 → 전송됨 → 응답 중 → 응답 완료`가 차례로 뜹니다. 모든 패널이 끝나면 비교 기록이 저장됩니다.
4. 결과를 모아 두려면 전송 바의 **Markdown 복사** 또는 **저장**(앱 데이터 폴더의 `exports/`에 .md 파일).

**파일 첨부**: 📎로 파일 1개(8MB 이하)를 붙이면 모든 패널에 같이 올라갑니다.

### 응답 평가 (★ / ✕)

동시 전송이 끝나면 전송 바 위에 **응답 평가** 줄이 뜹니다.

- **★** 가장 좋았던 답 하나
- **✕** 실패한 답: 비었거나, 중간에 끊겼거나, 질문과 엉뚱한 답 (여러 개 가능)

누른 평가는 그 비교 기록에 저장되고 **성적표**의 "동시 전송 — 응답 평가" 표에 쌓입니다. 몇 주 쌓이면 "어떤 서비스가 내 질문에 잘 맞는지"가 숫자로 보입니다. 다시 누르면 취소됩니다.

## 3. 생성 → 검증: 한 AI가 쓰고, 나머지가 검토

중요한 답일수록 한 AI의 말을 그대로 믿기 어렵습니다. 이 모드에서는 한 서비스가 답을 쓰고, 다른 서비스들이 서로 다른 관점(**렌즈**)으로 그 답을 검토합니다.

1. 전송 바의 모드 버튼을 눌러 **생성→검증**(초록)으로 바꿉니다.
2. 각 패널 머리의 **역할 칩**을 눌러 `생성 → 검증 → 제외` 중 고릅니다. 생성은 하나만, 검증은 여러 개.
3. 검증 패널마다 **렌즈**를 고릅니다. 고르기 어렵다면 전송 바의 **프리셋…**에서 질문 종류를 고르면 한 번에 배정됩니다.

| 프리셋 | 이런 질문에 |
|---|---|
| 보고서·문서 | 사실·숫자·논리가 중요한 글 |
| 아이디어·기획 | 기획안, 전략, 장단점 |
| 코드 | 코드 작성·리뷰 |
| 빠른 검토 | 가볍게 한 번만 확인 |
| 결론·추천 검토 | 추천·의견이 들어간 답 |

4. **깊이**를 고릅니다: **빠름**(검증 1개·짧게) · **표준**(검증 3개) · **심층**(검증 전부 + 지적을 반영한 수정본까지 자동으로 받음).
5. **▶ 보내기**. 생성 패널이 답을 쓴 뒤, 그 답이 검증 패널들로 자동 전달됩니다.

### 렌즈

| 렌즈 | 보는 것 |
|---|---|
| 사실 | 숫자·날짜·인용이 맞는지, 출처가 있는지 |
| 논리 | 전제와 결론이 이어지는지, 비약이 없는지 |
| 위험 | 틀렸을 때 생길 손해, 빠진 예외 |
| 강점 | 잘한 점 (비판만 하지 않도록 균형) |
| 개선 | 더 낫게 고칠 방법 |
| 코드 | 버그·보안·성능 |
| 편향 | 의견 문장의 치우침, 이해관계 |
| 종합 | 위를 한 번에 짧게 |

### 판정 요약 카드 읽는 법

검증이 끝나면 전송 바 위에 **판정 요약** 카드가 뜹니다. 패널의 긴 원문보다 이 카드를 먼저 보세요.

- **상단 줄**: `등급 신뢰 1 · 수정 2`처럼 검증자들의 판정 분포. 검증자 둘 이상이 같은 문장으로 짚은 지적이 있으면 **공통 지적**으로 따로 보여 줍니다(표현이 많이 다르면 묶이지 않습니다).
- **검증자 칸마다**
  - 등급: 신뢰 가능 / 일부 수정 필요 / 신뢰 불가
  - 지적 수: 심각 · 보통 · 경미
  - **확인됨**: 검증자가 맞다고 확인한 내용과 근거 (동의할 때도 이유가 남도록)
  - 핵심 지적 1~3줄
- **채택**: 지적을 읽고 **맞는 지적 / 틀린 지적 / 보류**를 누릅니다. 이 클릭이 쌓여서 성적표의 "어떤 서비스가 어떤 렌즈에서 정확한가"가 됩니다. 가장 중요한 버튼입니다.
- **지적 반영 수정본 요청**: 검증 내용을 생성 패널에 되돌려 고친 답을 받습니다(전송 1회 추가).
- **생성 원문 크게 보기**: 판정을 읽은 뒤 생성 답 원문을 크게 봅니다.

## 4. 성적표와 기록

헤더의 **성적표**를 누릅니다. 두 탭이 있습니다. (Supabase 로그인이 필요합니다. 아래 "두 기기 동기화")

### 집계 탭

- **렌즈 × 검증 모델**: 렌즈별로 각 서비스의 "맞는 지적 비율" = 맞음 ÷ (맞음 + 틀림). 채택을 누른 판정만 셉니다.
- **생성 모델**: 검증자들이 "신뢰 가능"으로 본 비율. 검증자 성향이 섞여 있으니 참고용입니다.
- **동시 전송 — 응답 평가**: 서비스별 ★ 최고 비율과 ✕ 실패 비율.
- 표의 칸이나 행을 누르면 그 숫자에 들어간 기록만 골라 **기록 탭**에서 보여 줍니다.

채택이 3건 이상 쌓이면, 생성→검증 모드에서 프리셋을 고를 때 전송 바에 **성적표 추천 반영** 버튼이 뜹니다(어느 서비스에 어느 렌즈를 맡기면 좋은지). 자동으로 바꾸지는 않고, 눌러야 반영됩니다.

### 기록 탭

지난 비교를 찾아 다시 읽는 곳입니다.

- 위의 검색창: 질문·답·검증 본문에서 찾습니다(공백으로 여러 단어 → 모두 포함).
- 종류: 전체 / 동시 전송 / 생성 → 검증
- 줄을 누르면 펼쳐집니다. 펼친 곳에서
  - 평가(★/✕)와 채택(맞는/틀린 지적)을 고칠 수 있고, 집계에 바로 반영됩니다.
  - **Markdown 복사 · .md 저장**
  - **입력창에 다시 넣기**: 같은 질문을 다시 보내고 싶을 때. 입력창에 넣기만 하고 자동으로 보내지 않습니다.
  - **삭제**: 한 번 더 확인한 뒤 지웁니다.

## 5. 비식별화: 개인정보·기관명 가리고 보내기

회의록·고객 자료처럼 이름·연락처·회사명이 든 내용을 외부 AI에 그대로 보내기 꺼려질 때 씁니다. 검사는 전부 이 컴퓨터 안에서 합니다.

전송 바의 버튼으로 모드를 고릅니다(누를 때마다 바뀜).

| 모드 | 동작 |
|---|---|
| **비식별화 검토** (기본) | 개인정보로 보이는 것이 있으면 보내기 전에 검토 패널을 엽니다 |
| **비식별화 자동** | 찾은 것을 모두 가리고 바로 보냅니다 |
| **비식별화 끔** | 검사하지 않습니다 |

검토 패널에서
- 가릴 항목에 체크(기본은 모두 체크). `홍길동 → [인물A]`, `010-… → [전화1]`처럼 기호로 바뀝니다.
- 놓친 단어는 직접 추가, 가리지 않아도 되는 단어는 **항상 허용**.
- **가린 채로 보내기** / **원문 그대로 보내기** / **취소**

첨부 문서(txt · docx · pptx · xlsx · PDF)도 글자를 꺼내 같은 기호로 가린 `.txt`로 바꿔 보냅니다. 이미지·스캔 PDF·hwp는 읽을 수 없어서 원본을 보낼지 첨부를 뺄지 묻습니다.

결과를 볼 때는 판정 요약 카드의 **원래 이름으로 보기**, 동시 전송 내보내기의 **원문 복원**을 켜면 이 컴퓨터에서만 원래 값으로 바꿔 보여 줍니다. 원래 값은 클라우드에 저장하지 않으므로, 앱을 닫은 뒤 지난 기록에서는 복원할 수 없습니다.

**한계**: 이름은 "홍길동 과장", "김민 씨"처럼 호칭·직함이 붙은 경우에 잡습니다. 한 번 잡힌 이름은 글 전체에서 호칭 없이 다시 나와도 같이 가려지지만, 처음부터 호칭 없이만 쓴 이름·외국인 이름·약어 기관명은 놓칠 수 있습니다. 검토 패널에서 직접 추가하거나 설정 → 비식별화의 **항상 가릴 단어**에 넣어 두세요.

## 6. 그 밖의 기능

- **🔒 임시 전송**: 켜면 이번 실행 동안 보낸 것을 기록하지 않습니다(평가·채택도 저장 안 됨). 앱을 다시 열면 꺼집니다.
- **접두어**: 모든 질문 앞에 붙일 문장(예: "답변은 한국어로, 출처를 끝에"). 워크스테이션별로 저장됩니다. 검증 프롬프트에는 붙지 않습니다.
- **📚 프롬프트 라이브러리**: 자주 쓰는 질문을 폴더별로 저장해 두고 눌러서 입력창에 넣습니다. `{{고객명}}`처럼 쓰면 넣을 때 값을 묻습니다.
- **워크스테이션**(헤더): 지금의 패널 구성·각 패널의 대화 주소·역할·렌즈·접두어를 이름 붙여 저장하고, 눌러서 되돌아옵니다. "보고서 검토용", "코딩용"처럼.
- **메모**(패널 머리): 패널에서 선택한 글을 메모로 저장합니다.
- **웹슬롯**(독): AI 서비스가 아닌 일반 웹 페이지도 패널로 띄웁니다(전송 대상은 아님).
- **전송 횟수**: 독의 서비스 이름 옆 숫자가 오늘 보낸 횟수입니다. 설정에서 서비스별 한도를 정하면 넘을 때 경고합니다(무료 플랜 제한 대비).

## 7. 두 기기 동기화 (선택)

맥 두 대, 또는 맥과 Windows에서 프롬프트 라이브러리·메모·비교 기록·성적표를 함께 쓰려면 [Supabase](https://supabase.com) 프로젝트가 필요합니다. 없어도 앱은 그 기기 안에서 동작하지만, **성적표·기록 탭은 Supabase 로그인 상태에서만** 열립니다.

1. Supabase 프로젝트의 SQL Editor에서 저장소의 `supabase/schema.sql`을 실행합니다(`jilseo_`로 시작하는 표만 만들어 기존 프로젝트와 섞이지 않음).
2. 앱 **설정 → Supabase**에 Project URL과 **Publishable key**를 넣습니다. Secret key는 넣지 마세요.
3. 같은 설정 화면에서 Supabase 계정으로 로그인합니다. 헤더의 **설정 ●** 점이 로그인 상태입니다.
4. 기기마다 **이 기기** 이름을 다르게 정해 두면 기록에 어느 기기에서 보냈는지 남습니다.

오프라인이거나 로그인이 풀린 동안의 기록·평가는 **대기열**에 모였다가 로그인되면 순서대로 올라갑니다(헤더 "설정 (2)"의 숫자).
연결이 안 되는 동안에는 5분마다, 그리고 앱 창으로 돌아올 때 다시 시도하므로 복구되면 저절로 올라갑니다.

**무료 플랜이라면**: Supabase 무료 프로젝트는 7일 동안 요청이 없으면 일시 중지됩니다(대시보드에서 Restore로 복구, 몇 분 걸림). 이 저장소를 포크해 쓴다면 저장소 **Settings → Secrets and variables → Actions**에 `SUPABASE_URL`(Project URL)과 `SUPABASE_PUBLISHABLE_KEY`를 넣어 두세요. `supabase-keepalive` 워크플로가 3일마다 가벼운 읽기 요청을 보내 중지를 막고, 실패하면 GitHub가 메일로 알려 줍니다.

| 한 서비스만 "실패" | 그 패널에서 로그인·팝업·약관 동의 화면이 떠 있지 않은지 확인 → 헤더 **진단** |
| 여러 번 계속 실패 | 서비스 화면이 개편된 경우입니다. **진단** 결과와 함께 [이슈](https://github.com/dhicttech-source/jilseo/issues)로 알려 주세요. 고칠 줄 알면 **셀렉터 JSON 폴더**의 해당 파일을 고치고 재시작 |
| 답이 비어 있음 / 중간에 끊김 | 무료 플랜의 긴 질문(약 3천 자 이상)·검색 질문에서 자주 생깁니다. 질문을 줄이거나, 검증 렌즈는 다른 서비스에 맡기세요 |
| 판정 카드에 "판정 블록 없음" | 검증 서비스가 정해진 형식을 안 지킨 경우. 패널 원문을 직접 읽고, 반복되면 다른 서비스에 그 렌즈를 맡기세요 |
| 성적표가 안 열림 | 설정에서 Supabase 로그인 상태(●)인지 확인 |
| "Supabase에 연결할 수 없습니다" | 무료 프로젝트가 일시 중지됐을 수 있습니다. Supabase 대시보드에서 Restore → 몇 분 뒤 앱이 저절로 다시 연결하고 대기열을 올립니다(기다리기 싫으면 설정에서 **저장**) |
| 창을 가려도 되나? | 됩니다. 다른 창에 가려지거나 화면이 잠겨도 전송·수집은 계속됩니다. 단, 컴퓨터가 절전에 들어가면 멈춥니다 |

## 용어

- **스테이지**: 패널들이 나란히 놓인 가운데 영역
- **동시 전송**: 같은 질문을 스테이지의 모든 패널에 보내기
- **생성 → 검증(파이프라인)**: 한 패널이 답을 쓰고 나머지가 검토하는 모드
- **렌즈**: 검증하는 관점(사실·논리·위험 …)
- **프리셋**: 질문 종류별로 역할·렌즈를 한 번에 배정하는 묶음
- **깊이**: 검증에 쓸 패널 수와 판정 길이(빠름·표준·심층)
- **판정 블록**: 검증 답 끝에 정해진 형식으로 붙는 등급·지적 수·확인·핵심 줄. 앱이 이것을 읽어 카드로 보여 줍니다
- **채택**: 지적이 맞는지 사람이 표시하는 것. 성적표의 원재료
- **비교 기록**: 한 번 보낸 질문과 모든 답·검증·평가를 묶은 기록 한 건
